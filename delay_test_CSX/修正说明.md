# CSX延迟测试v2

本包替换上一包的main.c、monitor.py、monitor_auto.py，三个文件一起使用。
不改CAPSense参数，不改UART配置，保留SCB0/DELAY_UART/115200 8N1。
main.c按互电容预处理规则，仅对输出副本执行 maxRawCount-min(scan_raw,maxRawCount)，
使raw_pre成为软件滤波前、已完成方向转换的计数；不改传感器内存，不重复反转。
库仍通过原ProcessAllWidgets完成滤波、基线、diff和Status计算，LED逻辑不变。
修复monitor.py逐行绘图接收效率，改为批量接收、定时绘图，显示最近10秒。
CSV仍保存全部接收帧；窗口标题显示保存帧数、最新板上时间及Status。

操作：
1. 用本包main.c替换实际工程文件，Build、Program。SW2拨UART，关闭其他串口软件。
2. 两个Python脚本替换到同一目录，使用原Python环境。
3. 执行（COM5替换为实际端口）：

    python monitor_auto.py --port COM5 --out csx_iir64_v2.csv --count 2

4. 等待3秒，确认窗口标题时间持续前进。
   按住3秒（LED亮且图中Status应为1），松开等待3秒；重复至少3次。
   最后松开并等待曲线恢复，关闭图窗口或Ctrl+C，自动分析。
5. 检查events.csv及summary.csv；若仍异常发原始CSV及编译报错/运行截图。

旧CSV共206帧，只覆盖板上29.002到31.052秒，全程Status=0，没有录到完整按压。
它的采样周期均为10ms，时间轴正常。
该段raw_pre=9808..9844、raw_post=6547..6560、baseline=6552..6553。
以16384为转换上限可使旧raw_pre回到6540..6576附近，与滤波后静置水平一致。
这支持此前缺少CSX反转的判断；新固件用库运行时maxRawCount，不写死16384。
旧CSV没有按压，不能用于验证延迟，也不建议拿旧记录与v2混合统计。

验证：Python语法通过；旧CSV周期及转换后静置水平检查通过。
